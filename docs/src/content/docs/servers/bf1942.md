Compose path: bf1942. Image: bf1942.

Built on the shared [runtime-base](/reference/images/) image. The Dockerfile bakes the LinuxGSM-hosted `bf1942_lnxded-1.61-hacked-to-1.612` archive into the image as a seed, then copies that seed into the data volume the first time the container runs. You must own Battlefield 1942.

:::note[Requirements]
- You must own Battlefield 1942
- Persist `./data` for the server install, mods, and any config you edit
- Publish UDP **14567** and TCP **23000**
:::

## Ports

| Port | Protocol | Purpose |
| --- | --- | --- |
| 14567 | UDP | Game traffic, fixed, not configurable by env var |
| 23000 | TCP | Status/query port used by the bundled `bfpridaemon`, fixed |

Neither port has an environment variable override. Both values come from the LinuxGSM archive's own `start.sh` defaults.

## Environment

| Variable | Default | Purpose |
| --- | --- | --- |
| `BF1942_EXTRA_ARGS` | (empty) | Extra flags appended to `./start.sh +hostServer 1 +dedicated 1 ...` |

This is the only variable the entrypoint reads. Battlefield 1942 has no hostname, map, or player-count env vars, everything else comes from the config files inside the seeded data volume or from flags you add through `BF1942_EXTRA_ARGS`.

## Data volume

The data volume mounts to `/opt/bf1942`. On first start (or whenever `.lgsm-seed-complete` or `bf1942_lnxded` is missing from the volume), the entrypoint wipes anything in the volume except `.gitkeep` and copies the baked-in seed over it, then creates `.lgsm-seed-complete`. After that it leaves the volume alone.

The seeded tree includes `bf1942_lnxded`, `start.sh`, `fixinstall.sh`, the `bfpridaemon` status daemon source, and `mods/bf1942/archives/bf1942/levels/*.rfa`. There is no generated `server.cfg`, all server settings (hostname, map rotation, player count, rcon) live in the mod's own config files under `mods/bf1942/`. Edit them directly on the host with the container stopped.

Because a reseed deletes everything already in the volume, do not delete `.lgsm-seed-complete` or `bf1942_lnxded` unless you actually want to discard any config changes you made and start from the baked-in seed again.

## Updates

`ci/server-catalog.sh` lists no update env var for `bf1942`, so `./tools/gs update bf1942` is not available. See [Ops](../guides/ops/) for backup and restore, which do work for this server since it has a normal `data` volume. To pick up a newer archive you have to change the `LGSM_URL`/`LGSM_MD5` build args in the Dockerfile and rebuild the image.

## Healthcheck

`process` kind: the container is healthy while a `bf1942_lnxded` process is running (`pgrep -f bf1942_lnxded`). `start_period` is 180 seconds.

## Compose

```bash
docker compose -f bf1942/docker-compose.yml up -d
```

## Docker run

```bash
docker run -d --name bf1942 --restart unless-stopped --init \
  -p 14567:14567/udp -p 23000:23000/tcp \
  -v "$PWD/bf1942/data:/opt/bf1942" \
  -e BF1942_EXTRA_ARGS="" \
  {{IMAGE_PREFIX}}/bf1942:latest
```
